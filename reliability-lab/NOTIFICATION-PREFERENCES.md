# Success notification preferences — final owner-approved scope

## Settings and defaults
- Show success notifications: Yes/No, default Yes (preserve explicit existing preference).
- Show while Shelf is open: Yes/No, default No for missing preference. When Yes, allow one success notification whether Shelf is open or closed. When No, suppress success notification on ALL delivery surfaces while the relevant Shelf is open; preserve closed-Shelf success delivery. Master No suppresses all success notification delivery including custom and native fallback, and dismisses active success notices. Disable subordinate settings while master is off without resetting their saved values.
- Position: Center / Bottom-right; default Bottom-right with safe viewport inset.
- Size: Small / Standard / Large; default Large. Large preserves exact current 0.3.29 notification dimensions, artwork proportions and typography at the same viewport where they fit. Standard approximately 80%, Small approximately 60% of baseline linear dimensions; these are sizing targets subject to legibility, hit targets and responsive fit. Scale only the notification, never the Shelf. Preserve explicit preferences, validate invalid/missing values.
- Position and size apply to existing custom Console Era success notification, not OS-native fallback geometry. No other notification redesign. Preserve PNG, provider colors, approved animation timing, ten-second expiry, X dismissal and reduced motion.

## Implementation boundary and safety
Use existing createClosedShelfSaveNotice (src/chrome/save-notice.mjs), existing visualFeedback preferences and existing custom renderers; inspect actual app, shelf, page and native paths. Do not introduce another event producer or notification engine. Gate eligibility before ANY custom or fallback delivery and recheck relevant window Shelf state at asynchronous delivery boundaries. Retain operation identity, deduplication, existing coalescing and native fallback semantics; one successful delivery surface per event. An acknowledgement timeout is not proof of non-delivery: use existing delivery deadline/identity contracts and ensure late ACK/render cannot create duplicate fallback notices. Do not mutate or gate verified-save processing, badge increments, Queue, History, receipt persistence, in-Shelf card pulses, error/reconnect notices or actual saves. Master disable and open-Shelf eligibility changes must invalidate pending ineligible notifications and dismiss active ineligible notices without replay on re-enable. Guard expiry and dismissal by generation; stale timers or async clears must not dismiss a newer notice. Position/size changes apply on next notice (or update active custom notice in place without restarting animation or expiry); no replay. Preserve existing permission restrictions and notification fallback on unsupported pages. No extra permissions.

## Acceptance
Baseline capture first. Test all four master/open-Shelf combinations, existing explicit preference migration, restart, multiple windows and Shelf open/close during queued delivery, app/shelf/page ACK success/failure/timeout and late ACK, native fallback, rapid verified operations, duplicate events, disable during delivery, re-enable, older timer/new notice, position/size changes, all provider palettes, narrow/wide viewports, reduced motion, keyboard dismissal and exact Large baseline geometry when it fits. Assert independent saves, receipts, badges, History, Queue and error behavior unchanged. Separate fixture/browser/native evidence; no claims of unexecuted tests.
