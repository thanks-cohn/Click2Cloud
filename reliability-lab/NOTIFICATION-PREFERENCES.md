# Success notification preferences — final owner-approved scope

## Settings and defaults
- Show success notifications: Yes/No, default Yes (preserve explicit existing preference).
- Show while Shelf is open: Yes/No, default Yes for missing preference. When Yes, allow one success notification whether Shelf is open or closed. When No, suppress success notification on ALL delivery surfaces while the relevant Shelf is open; preserve closed-Shelf success delivery. Master No suppresses all success notification delivery including custom and native fallback, and dismisses active success notices. Disable subordinate settings while master is off without resetting their saved values.
- Dismiss on hover: Yes/No, default Yes. Applies only to custom success notifications; a genuine pointer hover over the currently visible notification dismisses that instance immediately. No means hover does nothing. Preserve X, keyboard dismissal and ten-second expiry. Persist independently; disable this subordinate setting while master is off without resetting it.
- Position: Center / Bottom-right; default Bottom-right with safe viewport inset. Owner corrected baseline observation: all skins show bottom-right with Shelf open and center with Shelf absent. One universal position preference. Both Center and Bottom-right are mandatory on closed-Shelf custom surfaces. With Shelf open, honor Center if feasible within existing architecture; otherwise retain the existing bottom-right placement. Bottom-right must work in both states. No separate position preferences and no unnecessary open-Shelf architecture changes.
- Size: Small / Standard / Large; default Large. Large preserves exact current 0.3.29 notification dimensions, artwork proportions and typography at the same viewport where they fit. Standard approximately 80%, Small approximately 60% of baseline linear dimensions; these are sizing targets subject to legibility, hit targets and responsive fit. Scale only the notification, never the Shelf. Preserve explicit preferences, validate invalid/missing values.
- Position and size apply to existing custom Console Era success notification, not OS-native fallback geometry. No other notification redesign. Preserve PNG, provider colors, approved animation timing, ten-second expiry, X dismissal and reduced motion.

## Implementation boundary and safety
Use existing createClosedShelfSaveNotice (src/chrome/save-notice.mjs), existing visualFeedback preferences and existing custom renderers; inspect actual app, shelf, page and native paths. Do not introduce another event producer or notification engine. Gate eligibility before ANY custom or fallback delivery and recheck relevant window Shelf state at asynchronous delivery boundaries. MANDATORY: retain the new custom Console Era notification as primary and the intentional existing native Windows/Chrome success fallback when custom delivery genuinely fails. The proposed removal of native fallback is canceled; do not delete or disable it, change OS-wide notification settings, or remove permissions. Investigate the reported unexpected native notification, distinguishing legitimate fallback from duplicate or premature delivery. Retain operation identity, deduplication, existing coalescing and native fallback semantics; one successful delivery surface per event. An acknowledgement timeout is not proof of non-delivery: use existing delivery deadline/identity contracts and ensure late ACK/render cannot create duplicate fallback notices. Do not mutate or gate verified-save processing, badge increments, Queue, History, receipt persistence, in-Shelf card pulses, error/reconnect notices or actual saves. Master disable and open-Shelf eligibility changes must invalidate pending ineligible notifications and dismiss active ineligible notices without replay on re-enable. Guard expiry and dismissal by generation; stale timers or async clears must not dismiss a newer notice. Hover dismissal must be scoped to the current notification generation, not its operation processing or future notices. Avoid document-wide hover listeners, synthetic hover dismissal on mount, touch taps being mistaken for hover, or click-through to underlying page controls. Preserve accessible keyboard dismissal and existing event isolation. Dismissal must not trigger native fallback or replay. Native OS fallback is not subject to custom hover behavior. Position/size changes apply on next notice (or update active custom notice in place without restarting animation or expiry); no replay. Preserve existing permission restrictions and notification fallback on unsupported pages. No extra permissions.
