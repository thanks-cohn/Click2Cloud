# Candidate API and trusted ports

```js
import {createRemoteSaver, createWorker, cloudflareR2Writer, sourceFromClick}
  from './src/index.mjs';
const saveRemote = createRemoteSaver(trustedHostPorts);
const result = await saveRemote({
  operationId: 'unique_logical_operation_123',
  source: {url: 'https://approved.public.net/file', filename: 'file.bin'},
  destination: {provider: 'cloudflare-r2', connectionId, accountId,
    bucketName, prefix: 'exact/prefix', conflictPolicy: 'keep-both'}, signal
});
```

Operation IDs: 16–128 ASCII alphanumeric/underscore/hyphen, generated by the authorized host with sufficient randomness; never URL hashes. New ID means a new save. Destination strings are not grants. Prefix is empty for bucket root, otherwise exact relative path without trailing slash, empty/dot segments, backslashes or controls. Unicode and extensions are preserved. R2 keys are bounded to 1024 UTF-8 bytes. Arbitrary name inference, menu labels and last-use defaults are absent. sourceFromClick takes media before link before page; it emits only URL and filename, no listeners.

Results have `state`, machine `code`, `operationId`, and normalized destination where valid. States: verified, failed, blocked, uncertain, cancelled. A verified result adds a receipt with key, size, etag, version, operationId, destination and proofKind independent-head-version-size. It means metadata/version/size confirmation through a fresh authorized HEAD, not cryptographic source equality. Cancellation is known safe only before dispatch. Once dispatched, transport errors, malformed receipts, abort, lost authority or missing/mismatched proof are uncertain; inspect storage read-only by operation/key before any deliberate new operation. Conditional create conflicts are failed with CONFLICT. Prewrite source errors are conservatively blocked; they are never success. A thrown PUT is uncertain even if a particular provider error might prove rejection; this avoids unsafe retry assumptions.

## Browser/host ports (all trusted, no implementation supplied)

- `authorize(intent) -> boolean`: checks user/API source consent and exact destination, current login, scope and capability.
- `getPreparedWorkerCapability(intent) -> {destination, expiresAt, ...opaque}`: exact ready capability and authenticated endpoint, never deploy/login/activate. Tokens stay in trusted host transport, not intent/page worlds.
- `recheckAuthorization(intent, cap) -> boolean`: before dispatch and after independent proof; must inspect current authority rather than cached UI state.
- `authenticatedRequest(cap, intent, {signal}) -> parsed Worker JSON`: exactly one POST to trusted HTTPS /remote-save. Must authenticate, reject redirects, honor signal, enforce response size/deadline and never retry writes. Never put bearer in URL. Only URL/filename/destination/operationId cross the transfer boundary.
- `verifyObject(cap, receipt, {signal}) -> fresh proof|null`: independently authenticate a read-only HEAD/stat of exact authorized R2 key. Must return destination, operationId from stored metadata, size, etag, version, key from trusted response. Must not echo the receipt as evidence. May call the writer.verify over a protected server-side read port; that read endpoint must enforce the same principal and destination scope. No public read endpoint is included.

A saver instance retains one promise per operation ID, with conflicting input rejected. Host must bound instance lifetime and retain no completed signed source URLs unnecessarily. Durable Worker claims, not this memory map, prevent duplicates across restarts. Durable claim key must scope principal + connection/account/bucket + operationId and atomically bind the complete intent; mismatched duplicate claims must not dispatch again. Retain claims through all ambiguous outcomes; a timeout is not permission to clear/replay. Do not retry a claim as a second write.

## Worker ports

`createWorker(ports).fetch(Request, env)` is a standard Worker-compatible handler. Wrapper/export wiring is deferred to deployment review. It only permits POST /remote-save, bounds request parsing and has no CORS/public asset route.

`authenticate(request, env, intent)` validates the caller token/principal server-side, resolves exact approved destination, and returns `{destination, expiresAt, storage, allowedHosts, maxBytes, maxBufferBytes, timeoutMs}`. storage must be the trusted R2 binding for that account/bucket; never looked up from arbitrary client names. allowedHosts is an exact approved public source-host list. All three limits must be positive safe integers and buffer limit ≤ maxBytes. Never store hard-coded account identity as authority in source.

`claimOperation(cap, operationId, intent)` is the durable atomic dedupe/security prerequisite, true for first authorized claim, false for any retained duplicate. A transactional Durable Object or equivalent strong store is required; eventual-consistency KV alone is insufficient. `recheckAuthorization(cap,intent)` runs immediately before write. `fetch` may be injected; production defaults to Worker fetch. Production FixedLengthStream is used for known lengths; a test implementation is not shipped as production. No credentials in env are enumerated or logged.

## Worker writer port

`kind`, `capabilities.conditionalCreate`, `prepare({destination,filename,operationId,signal})`, `write({prepared,body,length,contentType,operationId,signal})`, `verify({receipt,signal})`. prepare selects a key; write is single-shot conditional create and returns conflict or exact receipt; verify is a new read, not an ingest acknowledgement. Only R2 is accepted now. No source URL/provenance is passed to a writer. R2 implementation uses storage.head/put and FixedLengthStream. Provider checksums/multipart are not implemented.

Future caller sketch: existing V3+1 registrar and API resolver authorize exact SaveIntent → remote saver → verified outcome → existing completion owners. Map cloudflare/bucket/path identities explicitly to cloudflare-r2/bucketName/prefix. A returned uncertain state must never trigger History success or automatic upload replay. This is documentation only.
