## P0 deliverables (actual code and tests)

1. **Canonical, versioned state:** connection IDs, provider kind, actual account, R2 bucket, exact prefix, revision, discovered/paginated folder nodes, scope and freshness, configured endpoints, labels, explicit default, chosen mode and depth. Persistent snapshots and migrations with rollback/checkpoints; never infer authorization from cached names.
2. **One deterministic, pure menu compiler:** produce validated actionable IDs and stable MenuSpec for Portal and Chrome. Support multiple Cloudflare R2 buckets and independent S3 providers. Default simple label = last folder name, else bucket. Reject or explicitly resolve exact sibling/label collisions via user choice. No path collisions across accounts/buckets. No raw secret in IDs, logs, menu labels or exports.
3. **Three independent mode modules:** Simple flat, Nested/Narrow manually selected authorized endpoints + natural ancestors, Depth all discovered eligible folders to per-bucket configured 1–10+ levels. Maintain `src/modes/simple/`, `src/modes/nested/`, `src/modes/depth/` or equivalent **separate config, version, revision, validation, projection and tests**; none may directly write another's config or import another's internals. They share only read-only authenticated inventory, an identical MenuSpec contract, shared dispatch and registration. Switching mode never resets or mutates inactive modes. Test replacement of one mode without modifying the others.
4. **True production Chrome semantics:** REDOWN provider root; Cloudflare direct-save leaf when one verified default; when extra destinations exist it expands to configured siblings then actual separator then **Home last**, saving to the same exact default. No 'Home' navigation fallthrough. Google Drive/Dropbox/OneDrive stay flat provider leaves and never drive the R2 projection. Preserve exact route IDs, idempotent registration, update/retry, MV3 restart. Follow owner-approved semantics from REDOWN's `NEED_TO_DO/CODEX/logic-tables.md` as input, but implement the independent engine **here**, not by modifying REDOWN's production extension.
5. **Minimal working right-click workbench, not another Explorer:** on a real user-selected image, expose the same pure MenuSpec and dispatch one real original-byte save via an authorized host. Include actual native-Chrome right-click registration and a focused web menu preview, clearly distinguishing what Chrome can render. No compressed-preview uploads or disk staging when supported fetch/stream path exists. Do not build a second cloud file manager, Shelf, History system, or provider OAuth UI beyond what is needed for this narrow harness.
6. **Intuitive path editor + real REDOWN dashboard maintenance controls:** one typeable autocompleting path field with no focus loss; three independently side-scrollable Parents/Siblings/Children pill rows; click to navigate; independent Simple/Nested/Depth settings; per-bucket depth; explicit + add/remove, duplicate-label Yes/No and Save Changes / Apply with truthful native Chrome ack. **Refresh** = read-only discovery/listing. **Activate Buckets** = actual authenticated REDOWN Worker preparation/verification/retry-failed. Do not conflate either with conditional **Enable R2** enrollment, or expose a disabled activation facade as a finished implementation.
7. **Reuse the extracted Universal File API and real R2 adapter:** use `createClick2CloudFileApi({send,http})` from `src/explorer/index.mjs`, supplying **trusted authenticated** host transports matching REDOWN's actual background and Cloudflare REST contracts. Route listing with delimiter/pagination, real empty-folder markers, upload staging/byte readback, KEEP BOTH, copy/move, download, status, and failures through `api.run()` or `api.batch()` instead of constructing a second provider stack. The Cloudflare lab has 19 live REDOWN Worker Service Bindings, including the newly created `redown-redown-404399` bound to the real `redown` bucket. Service bindings do **not** grant Chrome OAuth sessions or private Worker tokens. Expose no arbitrary unauthenticated Worker fetch proxy; keep worker secrets in Cloudflare. Respect least privilege and data integrity. Important architecture conflict: REDOWN's historical `remoteIngest` forwards the original URL to its own Worker, while Click2Cloud's newer destination-provider privacy goal specifies only bytes and minimal metadata. **Resolve and test this difference explicitly**, without claiming the old URL-forwarding flow already meets the new goal. No true-remote or uncapped-size claim without live representative E2E proof.
8. **One dispatcher and trustworthy receipts:** real Portal and Chrome call the same `SaveIntent` dispatcher; confirmed success/history/counters/celebration **only** after real provider-confirmed receipt. A click pulse may acknowledge dispatch immediately but must not count as saved. No false positive on login failure, timeout, ambiguous upload or retry.
