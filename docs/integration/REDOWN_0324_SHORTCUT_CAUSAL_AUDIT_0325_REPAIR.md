These observations establish delivery and discovery for that sample. They leave the Chrome grant, the Shelf activation, and the application outcome to be measured separately. ### Shelf Files and History

- **Latent cause verified on official Chrome.** A Global command delivered no Tab. The old handler found a focused window via `getLastFocused().then(...)`, then Chrome rejected the resulting call with “`sidePanel.open()` may only be called in response to a user gesture.” Both baselines contain the same path. A native callback for the identical window lookup preserved the gesture in the same browser, and installed repair probes opened real Files and History. This establishes a gesture failure after successful window discovery. The owner's Windows command scope and Windows rejection text remain unverified. [Adapter](../../src/chrome/provider-panel.mjs) · [Chrome Side Panel API](https://developer.chrome.com/docs/extensions/reference/api/sidePanel#method-open)
- **Separate UI boundaries verified.** Once open, the native Shelf must boot or receive the intent, show the right view, and acknowledge actual UI state. A runtime message with no receiver can race panel boot. The pending command sequence survives through session storage and the Shelf can retrieve it once ready. The layout code shared by both baselines could hide a pinned search popover on leaving Files and try to focus its hidden input on return. The continued candidate reproduced that focus failure from History. Reopening the hidden popover before focusing passed the installed one-press checks. Files success requires the visible filename input and native document focus. History success requires the rendered view or the native close event. A separate native Linux probe found that `sidePanel.open`, `window.focus()` and input focus could leave keyboard input with a webpage while the Shelf was already visible. In that case REDOWN reveals search and reports keyboard focus pending. [Shelf UI](../../extension/app.mjs) · [Files popover](../../extension/explorer-layout.mjs) · [Chromium Side Panel focus implementation](https://github.com/chromium/chromium/blob/3fefdd7e0c0b7eba52585641422af521505fa95e/chrome/browser/ui/views/side_panel/side_panel_coordinator.cc#L142-L176)
- **Owner notification error UNVERIFIED.** The browser-command paths call the Side Panel API and use internal `runtime.sendMessage` for intent and feedback. The app feedback handler renders a Shelf notification. The command paths do not call `chrome.notifications.create`, open a popup, or ask a notification click to provide an activation. Provider attention and the toolbar action have separate entry points. When no Shelf receiver is available, the trace records that gap. An OS notification, another extension path, or the exact owner-visible error cannot be attributed without the original error and its source context. ### Windows keyboard layout and binding

The owner reports that removing the repeatedly selected Spanish layout improved screenshot behavior. A Windows language-switch chord can compete with Alt+Shift combinations before they reach Chrome. The 17 delivered events still include the two failed Shelf actions, so layout interference cannot account for all downstream failures in that sample. Treat layout interference as a **HYPOTHESIS** for missed or changed key delivery. In a disposable Windows test profile, compare the same Chrome scope and key assignment using both layouts, record the taskbar input indicator before and after each physical keystroke, and compare the event and outcome. Use the effective bindings in Chrome settings, including the owner’s Alt+Shift+F and Ctrl+Shift+F when each is assigned. There is no manifest rebinding or OS change in the repair. ## Durable diagnostics

The existing bounded Chrome-local Glaciaring breadcrumb store retains the latest shortcut attempts alongside the prior diagnostic entries. Each command has a UUID. The screenshot UUID is also the regular History operation ID. The Shelf retains the command UUID and sequence in trusted session intent so a worker restart can still correlate the real UI acknowledgement. The store coalesces steps, retains 32 entries for at most seven days, uses its existing batch timer and excludes URLs, credentials, pixels, tab IDs and window IDs from shortcut traces. Quota or interruption can leave gaps. The absence of terminal evidence remains unverified or incomplete.

Files and History trace command receipt, handler, browser target, actual Shelf readiness, dispatch, acknowledgement and verified UI state. Search focus pending is distinct from successful focus. Offline Files can reveal a focusable field and accept typed text while startup finishes. Submitting without a connected folder shows an explanation and makes no provider request. Screenshot traces distinguish window, tab, document, native capture, PNG, cloud save, verified output and durable History. RAW ZIP uses the existing explicit consent gate and preserves only recognized fixed Chrome messages, with dynamic window IDs, tab IDs and URLs redacted. SECURE ZIP retains categories and removes Chrome message text. Settings → Debug recorder → Export scope → Chrome shortcuts exports `chrome-shortcuts.jsonl`.
