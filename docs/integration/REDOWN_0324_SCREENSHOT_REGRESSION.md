The later audit includes the owner’s 17-event trace and the current tabless recovery and durable diagnostics design. [Current audit](REDOWN_0324_SHORTCUT_CAUSAL_AUDIT_0325_REPAIR.md)

The owner reports that Alt+Q captured and saved screenshots in 0.3.23. In 0.3.24, Chrome displayed “Chrome did not grant permission to capture this tab.” The owner’s Ctrl+Shift+F assignment also stopped opening Files and focusing filename search. Chrome displayed “Chrome could not change the Shelf. Try the shortcut again.” The owner reports both symptoms in a fresh Chrome profile and working behavior in Edge. Official Google Chrome on Windows is the primary acceptance target. [Owner request](../../codex-request-redown-0325-chrome-first-shortcuts-desktop-capture-2026-11-22.md)

## Confirmed issues and open causes

- **Capture grant.** Required web host access can make `Tab.url` readable even when the particular command has supplied no `activeTab` grant. A Chrome command scoped Global has no tab context to corroborate. Querying the last focused window in that case can target an unrelated tab and still fail at `captureVisibleTab`. The path is present in both versions. Whether the owner’s failing command used Global scope, delivered an incomplete tab, lost a grant, or hit a site or browser policy remains an installed Chrome question. [Chromium command dispatch](https://github.com/chromium/chromium/blob/3fefdd7e0c0b7eba52585641422af521505fa95e/chrome/browser/extensions/extension_keybinding_registry.cc#L303-L347) · [Chromium active-tab grant](https://github.com/chromium/chromium/blob/3fefdd7e0c0b7eba52585641422af521505fa95e/extensions/browser/permissions/active_tab_permission_granter.cc#L143-L238)
- **Shelf gesture and target.** Missing command-window context sends the original path through an asynchronous lookup before the gesture-gated call. An already-open Shelf search also invokes the native open again. Those are concrete failure paths, and Chrome can separately reject a missing window, unavailable configured panel, or missing gesture. The owner’s generic message and Edge comparison do not distinguish them. The broad host-permission diff alone has no demonstrated causal link to this rejection. [Chromium native open validation](https://github.com/chromium/chromium/blob/3fefdd7e0c0b7eba52585641422af521505fa95e/chrome/browser/extensions/api/side_panel/side_panel_api.cc#L71-L120) · [Chromium panel service](https://github.com/chromium/chromium/blob/3fefdd7e0c0b7eba52585641422af521505fa95e/chrome/browser/extensions/api/side_panel/side_panel_service.cc#L253-L281)
- **Shelf focus after opening.** `focusPendingSearch()` requires the Shelf document to own keyboard focus before acknowledging search. Chromium’s `SidePanelCoordinator::Show` returns without refocusing when the requested panel is already showing. Chrome has also tracked keyboard focus on first show in a separate browser issue. Check first open and already-visible Shelf while the webpage owns keyboard focus as separate installed cases, using real typing to verify focus. [Chromium same-panel fast path](https://github.com/chromium/chromium/blob/3fefdd7e0c0b7eba52585641422af521505fa95e/chrome/browser/ui/views/side_panel/side_panel_coordinator.cc#L142-L176) · [Chromium browser issue](https://issues.chromium.org/issues/486495151)

## Why the pre-release checks missed the reported failures

The release checks exercised packaged code, real Chromium storage and a fixture-rendered Shelf. Their fake Chrome calls could establish behavior after grant, command or API inputs were supplied. Chrome itself controls keyboard registration, update approval, active-tab grants, browser gestures and creation of the real Side Panel. The contemporaneous installed attempt stopped during unpacked extension installation with `UNPACKED_EXTENSION_DISABLED_BY_ADMINISTRATOR` on Linux browser `156.0.8078.79`. It recorded zero installed checks. The 0.3.24 built-in fixture success therefore left the primary Windows Chrome release gates unverified. [Verification report](REDOWN_0324_P0_VERIFICATION.md) · [Installed browser receipt](../evidence/redown-0324/installed-chromium.json)

The repository also has a headed screenshot integration script driven by X11 keys, with a disposable local HTTPS provider fixture. The 0.3.24 verification record does not show a successful run of this installed script against the comparison build. Its checked-in ordinary Files/search route uses `Alt+Shift+F` and sends two presses in already-open view cases. An unpacked Reload checks storage and shortcut carryover. That setup leaves the owner’s Ctrl+Shift+F, single-press focus throughout the Shelf, Windows product and channel, and real required-permission update approval to be checked independently. [Headed screenshot script](../../scripts/test-screenshot-browser.mjs)

## 0.3.25 changes and regression tests

The earlier candidate rejected a command that supplied no valid browser tab and window. The continued repair resolves a stable focused tab and lets Chrome enforce its actual grant, as documented in the later audit. With a supplied tab it checks that the active document is still in the same focused normal window before and after native capture. Structured diagnostics distinguish missing tab grant, inaccessible page, capture policy, rate limit and other native failures. The test exercises both commands, rejected contexts, changed documents, two-capture admission, readback and per-capture counting. [Capture checks](../../tests/screenshot.test.mjs) · [Badge checks](../../tests/daily-badge.test.mjs)

The Shelf uses Chrome's native callback for a tabless command when a Chrome window is focused. It keeps the direct gesture path for a command with a tab, shares pending native opens, restores the previous view after a rejected open and reports only a bounded error category. When Chrome leaves keyboard focus on the webpage while the panel is already visible, the command selects Files and reveals search. The handler acknowledges keyboard focus only once the Shelf actually receives it. A separate native probe found that `sidePanel.open`, `window.focus()` and input focus left keyboard focus on the webpage in this state. [Shelf checks](../../tests/shelf-history-toggle.test.mjs)

Browser command IDs and suggested chords are preserved. The manifest and Settings list Alt+Q, the alternate screenshot, Files/search and History in the requested priority. Settings exposes the actual binding and directs binding and scope changes to Chrome. History and exports render unavailable URL values as `N/A` without saving a replacement value or creating a placeholder link. [Keyboard checks](../../tests/release-0320.test.mjs) · [History checks](../../tests/history.test.mjs)
