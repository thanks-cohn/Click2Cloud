# Click2Cloud 0.3.20 export protocol

The ordinary Explorer **Download** action preserves individual object bytes. Folder Download recursively streams a ZIP whose entries and source reconciliation can be inspected offline. The Settings controls for custom-domain links, tags downloads and metadata downloads default to off. **Nest under Download** affects presentation when an optional download mode is enabled.

## Archive and receipt

- Files preserve relative paths under `files/`. A reserved `_click2cloud/` tree holds the optional manifest and sidecars and exactly one `RRReceipt-<UTC-millisecond-stamp>-<job-id>.json` per finalized directory ZIP. The timestamp and job ID are fixed when the download starts.
- Inventory uses paginated exact-prefix listing. The export compares strong ETag and byte size while reading. When both observations expose a version, metadata exports compare that as well. R2 cursor enumeration is an observation over time, so the receipt records coverage and lists changed or omitted objects individually.
- An invalid path, path collision, missing identity or stale metadata detected before an entry is opened can produce a marked partial ZIP. A stream that fails mid-entry aborts the archive and the file-system writer. Directory markers are listed as such, with no corresponding original file.
- The exporter streams ZIP32 entries and bounds inventory at 20,000 objects. It rejects output at the 4 GiB ZIP32 boundary. A size-verified local file is a separate result from archive finalization. The in-archive receipt records evidence available before the archive closes. It carries CRC-32 per written entry, without treating ETag as a content SHA-256.
- Debug **More → Downloads** shows browser-session progress, status and the receipt filename. The badge includes verified local results counted by original files. No diagnostic card stores receipt contents, and existing save History is independent of local export jobs. [Archive writer](../../src/explorer/download-archive.mjs)

## Cloudflare visibility and metadata

`getPublicUrls` uses the authorized Cloudflare custom-domain list. A mapping must have active ownership, active TLS and public access enabled. The resulting URL uses the exact encoded object key. WAF, custom routing or an application access policy can still affect a public request. The initial **Allow Public URL?** dialog opens domain input for the selected bucket. A domain can affect the whole bucket. This build verifies existing Cloudflare associations and leaves all domain administration with Cloudflare. The file editor stages a selection for copying and the directory editor uses that selection for grouped formats. Per-object persisted URL edits remain unavailable. [Cloudflare custom-domain API](https://developers.cloudflare.com/api/resources/r2/subresources/buckets/subresources/domains/subresources/custom/methods/list/)

Tags are read as a JSON array in the Click2Cloud custom metadata key `click2cloud-tags` when R2 exposes it. The editor uses NFC normalization, a UTF-8 JSON size estimate, and the 100-byte guard reserved from the requested 8,192-byte budget. Tag Save is disabled. The current provider path has no proven conditional metadata-only write that preserves an object version, bytes and unrelated metadata across competing edits. A tag download inserts and reads back a named PNG international text chunk in supported bounded PNGs. Other files use the original plus a companion JSON when tags are observed. All Metadata packages original bytes and the allowed observed metadata, with missing and redacted fields identified. [R2 Workers API reference](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/)

A provider rollout needs disposable-object tests for custom metadata visibility, conditional writes against competing versions, a current provider limit measurement and readback of unchanged content and HTTP metadata. It also needs disposable bucket tests for explicit domain registration and exposure scope. The fixture suite exercises active-domain filtering, URL encoding and grouping, tags and size accounting, PNG metadata, ZIP status and archive reconciliation without real provider changes.
