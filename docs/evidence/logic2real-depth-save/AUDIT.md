## Evidence

- **Projection fixture** means the canonical composite compiler and generated Chrome plan, using synthetic folder inventory. It can verify shape and exact bound routes.
- **DOM fixture** means the production Shelf HTML and app module in jsdom with a simulated extension message boundary. It can verify what changes the controls submit, draft behavior, and status text.
- **Routing fixture** means the production typed API, engine, and registrar, callback-backed fake Chrome, fixture CURRENT, and an in-memory object sink. It verifies exact save inputs at the transport boundary and fixture object keys.
- **Native Chrome and real R2** remain unverified for every scenario below. Chromium 156 exited with `socket() failed: Operation not permitted` at startup. The managed Chrome URL policy separately blocked `chrome://extensions/`. No authorized R2 test destination was available for provider writes. The broad test run did not complete after automatic review blocked a command associated with outbound access to `workers.cloudflare.com` because the transmitted data and authorization were unverified. All 66 focused tests and the extension build passed. The broader offline suite passed 352 of 353 tests. Its sole failure, the historical Simple golden-menu mismatch, also reproduces on the untouched baseline.

## Depth before and after

The Depth projector already treated depth as distance below the root, retained siblings and single-child branches, and produced direct boundary leaves. The first topology divergence was composite composition, which always kept a Depth bucket branch when a single bucket had children. The first refresh divergence was the background inventory union, which let removed prefixes survive a fresh crawl. The persistence response also lost discovery errors after a successful transaction, making a committed revision look like a failed write.

Depth 0 and invalid persisted depths remain rejected by validation. An omitted legacy limit defaults to 10. ## Verification and remaining gaps

- Fixture coverage includes lowering and raising depth, selecting and removing buckets, mode switches, close/reopen, failed writes, failed discovery, partial Chrome callbacks, retry without another configuration revision, and queued saves. A replay of an older commit reports supersession. Existing registrar tests cover restart recovery with callback-backed Chrome.
- Final DOM fixture exercised the actual manager Save controls for all three modes with simulated IPC. It confirmed that Narrow's title and Depth's typed numeric value survive a save and that the same request is retried after an interruption. The browser acceptance script was updated to use the new manager Save flow. The DOM fixture passed all three modes; the browser acceptance script remains blocked at browser startup.
- Native rendering, browser-level nesting limits, service-worker and extension restart on an installed build, provider credential states, and real object readback still require an extension-capable Chrome profile and an authorized R2 test bucket. There is no claim of a zero live logic2real gap.
