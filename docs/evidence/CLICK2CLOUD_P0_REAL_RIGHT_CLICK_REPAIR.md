## Remaining blockers and actual platform boundaries

1. **Live installed Chrome/Windows:** administrator-approved unpacked loading and the user's actual profile are unavailable here. Follow [live acceptance](CLICK2CLOUD_P0_LIVE_ACCEPTANCE.md). Native visual menu/click and deployed TRUE REMOTE save are not proven.
2. **Worker route:** environment proxy blocks the existing workers.dev host. No bypass or redeployment was attempted. Current run permits local implementation/read-only checks only; live setup/write approval must happen separately in the actual GUI/account.
3. **Direct pinned TCP reach:** Cloudflare explicitly blocks TCP to Cloudflare IP ranges and port25. Cloudflare-hosted source sites can therefore fail SOURCE_EGRESS_UNAVAILABLE. A separately authorized enforcing egress service is the feasible extension, not unsafe wildcard hostname fetch. HTTP/2-only peers are not supported by the HTTP/1.1 parser. Live networking remains untested.
4. **Large finalization:** R2 documents nominal 5 GiB single-PUT and ~4.995 TiB multipart capacity. Its table/footnote disagrees at the exact single-upload boundary; no boundary conformance measurement occurred. Safe conditional multipart completion is NOT_VERIFIED. The implementation stops at the conditional single-PUT service pathway; it does not advertise full multipart capacity or overwrite an existing key. Unknown-length spool parts remain in the chosen prefix, with extra storage/operation costs and no automatic cleanup.
5. **Very long active jobs:** DurableObjectState.waitUntil protects eviction for up to15min, not indefinitely. Progress is durable, the source stream is not. Eviction-safe source-range continuation needs stable source identity/range support and safe finalization (or authorized long-lived compute). Interrupted work is uncertain/read-only, never automatically replayed. DO claim storage, throughput and plan-specific CPU still require live measurement.
6. **OAuth:** same existing scopes/registration are preserved. Development API-token settings success does not prove registered OAuth provisioning/DO permission. Errors remain precise, no scope enlargement or fake readiness.
7. **Private Explorer sources/local files:** R2 remains TRUE REMOTE public-source only; no authorized private cloud-source integration is supplied. The GUI explains this and offers Download. Drive/Dropbox/OneDrive remain honest unimplemented entries. No MEGA/S3 driver added.
8. **Residual API/legacy work:** new meaningful save/setup/status/navigation/download actions share the typed API. Existing OS directory-handle staging still uses a trusted GUI CURRENT instance and lacks a stable opaque-handle registration port. Legacy unconfigured mutation/practice helpers are not certified or exposed. Redirect-final-path/MIME filename inference is not comprehensive; explicit API names, URL/query hints and validated Content-Disposition are supported. These are disclosed partial items, not silent completion claims.

Official constraints: [TCP](https://developers.cloudflare.com/workers/runtime-apis/tcp-sockets/#considerations), [TLS](https://developers.cloudflare.com/workers/runtime-apis/nodejs/tls/), [Worker limits](https://developers.cloudflare.com/workers/platform/limits/), [R2 limits](https://developers.cloudflare.com/r2/platform/limits/), [S3 API](https://developers.cloudflare.com/r2/api/s3/api/), [DO state](https://developers.cloudflare.com/durable-objects/api/state/#waituntil). Official source snapshots were read through allowed raw GitHub Cloudflare documentation; hashes in verification evidence identify those sources.
