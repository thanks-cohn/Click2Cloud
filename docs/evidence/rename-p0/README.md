## Candidate behavior

The existing transport checks the live OAuth account and R2 authority, plan and deployed Worker identity, scoped capability and supported file action. The API requires a receipt for the exact new key and operation before returning success.

The deterministic tests cover a current scoped plan, approved earlier build metadata, stale and missing plans, a changed right-click default, reconnect, wrong scope and revoked access, collision, a lost acknowledgement and a mismatched receipt. ## Windows Chrome and live R2 release check

1. From this branch run `npm ci --ignore-scripts --no-audit --no-fund`, then `npm run build:extension`. In Windows Chrome, open `chrome://extensions` and load `dist/click2cloud` unpacked. Confirm version 0.3.23 and extension ID `ajppphdiamdobknpamcheohmdbdbeoal`. Use an existing test-only Chrome profile with working OAuth and an already prepared R2 test bucket. Keep its existing extension ID and saved signing plan. If the test profile lacks an authorized connection, stop the live check.
2. Use the Cloudflare R2 dashboard or a permitted existing client to upload a small disposable PNG and a different PNG called `Taken.png` into a nested folder covered by that test Worker's existing binding. Record both SHA-256 values locally. PowerShell can compute them with `Get-FileHash .\Rename-original.png -Algorithm SHA256`.
3. In Explorer, right-click the disposable PNG and choose **Rename**. Type `Rename-explorer` and click **Save**. Verify that `.png` remains, the Explorer row is selected, the new key exists in R2, and the old key is absent. Download the new key independently and compare its SHA-256 to the original. Repeat with **F2** and **Enter**.
4. Open the image, double-click its title, and rename it again. Repeat using **F2**. Verify the title, current image and gallery navigation. In **Immersive View**, single-click the filename, type a name and press **Escape**. Check that the viewer stays open and the object is unchanged. Then commit another rename by clicking the title and pressing **Enter**. Repeat with **F2** from the viewer controls.
5. Attempt to rename to `Taken.png` and confirm the collision message. Check that both originals and their hashes are intact and no numbered replacement exists. Repeat a valid rename after an Explorer refresh, Shelf reopen, Chrome restart, extension **Reload** in `chrome://extensions`, and a stopped MV3 worker waking on the next Shelf command. Use `chrome://serviceworker-internals` to stop the test extension worker if available in that Chrome build. Repeat after a test-session reconnect and, if a second prepared test destination exists, after changing the unrelated right-click default.
6. To check negative cases, use only the disposable profile and test bucket. Try a folder outside an existing prefix-scoped binding and a disconnected test session. Confirm that both are blocked before mutation. Interrupt the connection during an in-flight test rename and inspect both keys in R2 before considering another attempt. For test records, keep only issue codes, safe target labels, Chrome/build version, screenshots and hashes.
7. With the existing native Cloudflare context-menu entry, save a separate disposable PNG to the prepared test destination. Verify the exact R2 key, matching bytes and corresponding History receipt. Clean up the disposable objects using the authorized test client.
