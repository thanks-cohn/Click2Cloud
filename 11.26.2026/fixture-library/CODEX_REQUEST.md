## P0: real Queue and History
- Every admitted file is visible in the real REDOWN Queue, with actual name, provider, progress, bytes and states, not fabricated UI entries; display pending/active/verified/failed/uncertain/cancelled and grouped folder progress. No invisibly bypassing production queue. Folder job expands into individual child rows with true progress. For thousands, virtualize or paginate, bounded memory; no dropping events. Keep ordinary queue controls working, including cancellation and provider distinctions.
- Individual uploaded files each receive their own durable History card through the normal persistence pipeline; show actual upload/verification status, provider, timestamp, filename, size, receipt and existing actions. Upload acknowledged but verification uncertain must not be presented as verified. Idempotent across restart/reconcile, immediate History refresh. Never generate extra cards just for readback.
- Explicit folder upload: exactly one folder History card instead of thousands of standalone child cards. Show folder name/path, provider, file count, aggregate bytes, completed/failed/uncertain counts, expandable/paginated child results and receipts, per-child existing actions where appropriate. Folder card is a UX grouping, NOT an excuse to omit per-file durable evidence. Mixed results must remain visible.
- Folder preview: determine the most frequent supported image format among successfully uploaded, preview-eligible folder descendants (normalize JPEG aliases; stable format tie-break lexicographically), then choose the smallest nonempty, verified, preview-decodable image of that format by original byte length; ties use normalized relative path. If the first candidate fails safe preview decoding, choose the next eligible file, then next ranked format; if none, use generic folder icon. Do not fetch or decode every child: use metadata then bounded lazy preview of candidates only. No SVG scripts, external resources, or active content. Preserve access controls, existing thumbnail cache bounds, and UI responsiveness. Internal batches do not create separate History folder cards.
