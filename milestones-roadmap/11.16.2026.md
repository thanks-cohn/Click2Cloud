# Click2Cloud — Milestones Roadmap
**Date:** 2026-11-16  
**Status:** Planned; do not confuse proposals with verified or shipped behavior.  
**Repository:** Click2Cloud  
**Principle:** Reliability first. UI themes, URL generation, and Chutey interoperability must never break right-click remote saving.

## 1. Establish a verified save baseline (release gate)
- Freeze the candidate build and record branch, commit, Chrome version/profile, destination configuration and diagnostic settings.
- Run **100 attempted right-click saves** across a reproducible set of website/source categories: Google Images (15), Bing Images (15), Yahoo Images (10), Wikimedia Commons (10), Unsplash (10), Pexels (10), Wikipedia (10), GitHub public files (10), other sites (10).
- Compare against ReDown Basic in a **separate clean Chrome profile**, with equivalent source URLs where applicable. ReDown Basic also gets 100 baseline attempts.
- Define success as **the correct bytes/object verified in the intended R2 bucket/key**, not a toast or queued receipt. Record first-attempt and eventual-after-retry success separately.
- Capture originating page URL and asset/source URL (when technically obtainable), target bucket/path, attempt ID, timestamp, enqueue/start/finish latency, retry count, status, and diagnostic/event references. Redact authentication secrets in shareable exports.
- Record failure classes (context menu missing, enqueue/rejection, fetch/source restriction, authorization, upload, wrong destination, duplicate, timeout, crash, unknown). Preserve minimal reproducible examples.
- Inspect startup/cold boot, service-worker lifecycle, reload/restart, menu fallback, queue recovery, and History/GO TO identity before declaring ready.
- **Exit:** Results, reproducible failure registry and actual destination verification reviewed; investigate every failure; goal 100% first-attempt verified saves (not a claim before measurement).

## 2. Finish themes and visual product presentation
- Make **“Bit o' Polish”** the default Click2Cloud theme (formerly envisioned as High Polish Mode).
- Preserve the current appearance intact as selectable **“Remote V1”** in the appearance/theme menu.
- Add a clean, extensible theme registry for future choices; separate visual tokens/components/animations from save routing, credentials, queue, worker, and persistence.
- Switch themes without interrupting active uploads or changing destinations. Preserve theme preference across browser restart.
- Polish Explorer, dropdowns, History loading states, visual consistency and accessibility while retaining core functionality.
- **Exit:** Remote V1 parity, Bit o' Polish visual review, theme-switch/no-save-interference tests.

## 3. Post-polish regression benchmark
- Run **200 saves per extension** (Click2Cloud and ReDown Basic): repeat the original 100 cases unchanged; add 100 new cases covering fresh URLs, repeated files, batches, reasonable concurrency, transient network interruption, browser restart/worker restart, and recovery.
- Measure verified first-attempt save rate, eventual completion, latency distribution, crash/reload counts and regressions relative to baseline. Keep the exact same 100-case subset for before/after comparisons.
- Archive structured RAW and privacy-redacted diagnostic exports, source/destination identity, test environment and failure reproductions.
- **Exit:** No unexplained functional regressions from visual changes; failures addressed or explicitly documented.

## 4. Restore individual Get URL (flagship creator feature)
- After reliability gates, restore **Get URL** on right-click of an R2 object.
- Support an explicitly configured, authorized Cloudflare R2 custom domain/public endpoint; generate a usable URL from verified bucket/object identity and correct encoding, not a guessed public address.
- Copy URL; test public reachability and permissions. Handle private/unpublished objects transparently.
- Keep URL generation modular: failures here must not block remote saving.
- **Exit:** Verified URL accuracy, correct object target, safe permissions behavior, copy-and-open test matrix.

## 5. Expand Get URL to bulk export
- Select a directory/prefix and generate/export a list of public URLs for included objects.
- Verify recursive scope/prefix handling, pagination, filename encoding, export completeness, duplicates and privacy.
- Premium packaging was **proposed**, not finalized: individual Get URL as candidate free feature; bulk export as candidate premium capability (earlier pricing idea: $5/month).
- **Exit:** Real-world creator demo: custom domain → R2 assets → exported URLs → static site/assets workflow.

## 6. Promote and validate Chutey-powered drag and drop
- Treat **Chutey drag-and-drop technology** as a flagship Click2Cloud differentiator, alongside Remote Save and Get URL.
- Demo direct dragging of stored cloud items into supported targets: **ChatGPT, Yandex, and Google services**. Verify exact product/site, browser, file type, size and drop-zone compatibility; do not claim universal support before tests.
- Build a compatibility matrix: image/file types, single/multiple selections, success confirmation, large files, clipboard alternative, permitted cross-origin/browser pathways and failure messaging.
- **Future R&D:** drag cloud objects directly into **local folders, other cloud providers' folders, and Click2Cloud folders**, with appropriate transfer/authorization mechanics. This is aspirational, **not shipped functionality**.
- **Exit:** Demonstrable, reproducible drag-and-drop cases with clear supported-target documentation.

## 7. Other promotional capabilities / experiments
- **Selected save allowance (2026-11-16): 7 free remote saves per day; unlimited daily saves with a valid paid license.** “7” is the playful good-luck number and reinforces daily use. Do **not** market “UNLIMITED FREE REMOTE”; market “7 free saves every day” and “Unlimited saves with a license.” The licensed tier has no app-imposed daily save-count limit, but remains subject to provider/storage quotas, acceptable-use rules and technical restrictions. Verify enforcement before publishing these as live entitlements.
- Promotional spot A: saving a large (~20 GB) collection remotely without filling local disk; use measured results rather than implying literally zero local caching.
- Promotional spot B: inexpensive domain → R2 custom domain → Get URL / bulk export → web-ready asset links.
- Bulk select with Ctrl/Shift and copy/paste to compatible apps; separately verify target support.
- Whole-folder uploads with folder hierarchy; previously discussed “100 images in 6 minutes” was an illustrative concept, not a measured benchmark.
- Experimental native desktop relay for local credentials and durable long jobs, subject to secure credential handling and authentication design; longer session duration subject to provider policies.
- Modular visual animation system: default animation, alternative animations/GIFs/images, possible user-provided source/URL, later selection of three and random/sequence playback; isolated from transfer engine.
- **Free/paid save-count policy decided:** 7 free remote saves per day, resetting daily; valid license unlocks unlimited daily remote saves. Final price, other license benefits, and exact enforcement details remain open. Specify timezone/reset policy, fair counting of retries/failures, cross-device integrity, and license expiry behavior before implementation.

## Promotional positioning
**Save it. Drag it. Share it.**  
Click2Cloud is a bridge from websites to R2 storage to everyday applications — not merely another downloader.

Three anchor demonstrations:
1. **Remote Save** — right-click web content straight into R2.
2. **Chutey Drag & Drop** — move stored cloud files into verified supported app drop zones.
3. **Get URL** — turn authorized stored objects into usable public links, eventually in bulk.

## Safety rails and documentation
- Preserve a known-good branch/commit and do not overwrite baselines during theme or URL work.
- Keep save, UI/theme, History, drag-and-drop and Get URL modules independent.
- Ship no claim of “crash proof,” universal drag support or unlimited capacity without evidence.
- Maintain one versioned benchmark dataset and changelog per build; every discovered failure becomes a permanent regression fixture.
