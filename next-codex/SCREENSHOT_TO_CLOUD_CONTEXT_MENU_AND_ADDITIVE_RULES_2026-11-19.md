## Card switch: EXCLUSIVE SAVE — only this one destination

**Exact card label:** **Exclusive Save** (ON/OFF), displayed on each saved Screenshot rule card under **More → Screenshot**, independently of its normal Active/Disable toggle and its far-right X Delete. Tooltip: **"Ignore other screenshot rules and save only to this folder."** The switch is saved persistently and can be turned off again to restore ordinary additive routing. Switching it does not delete, disable, change or permanently overwrite the other rules; every disabled rule card also remains visible until its far-right X is used.

**When an Exclusive Save card matches the current screenshot event:**
- Shortcut card: it applies ONLY when its assigned chord was pressed AND one of its website match entries matches the active page; no entries means All websites.
- Additive website rule card: it applies on a matching page whenever a supported Click2Cloud screenshot capture is user-triggered via an applicable existing screenshot shortcut; it does not initiate capture by itself.
- An Exclusive Save **website rule** already has one destination, which becomes the single exclusive destination. A **shortcut card** may have MULTIPLE destinations; turning Exclusive Save ON requires the user to choose exactly ONE **Exclusive destination** from its existing authorized folder list. It must never send to all its listed destinations when exclusive.
- A matching Exclusive rule **suppresses EVERY other matching shortcut-card destination and every other additive website-rule destination**, including all-sites rules, for this capture only. It writes ONE screenshot file to ONE authorized directory, with ONE screenshot capture and ONE browser upload to the existing Worker. It takes priority over the Settings **"Single file per screenshot per directory"** preference even when that preference is OFF.
- If the Exclusive card is disabled or its site/shortcut scope does not match, **do not** apply its override; evaluate the normal additive ON/OFF delivery policy. A website-rule Exclusive cannot make a screenshot happen without a user gesture.
- **Conflict control:** Recommend that turning Exclusive ON for one card explicitly turns it OFF for any previously exclusive card, with a clear inline explanation, so the user never faces two conflicting Exclusive owners of one screenshot. Never silently choose between two competing applicable Exclusive destinations. Preserve each card's normal Active state; switching exclusivity does not toggle activation.
- If an Exclusive shortcut card's chosen exclusive folder is removed from its destinations or becomes unauthorized, visibly require a valid new exclusive destination or switch Exclusive OFF before considering the rule operational. Never silently substitute another directory.
- Reuse the single trusted Worker fan-out, shared recorder and receipts; log one exclusive rule ID, selected target, and an explicit "other eligible rule intents suppressed by exclusive mode" state rather than falsely marking suppressed rules as failed. Still verify the one cloud object.

**User interaction example:** Existing `Ctrl+Shift+F6` All-sites shortcut card has `redown/screenshots/` and `redown/archive/`; a matching Google website-rule card points to `redown/google/`. On `google.com`, with Google **Exclusive OFF**, the normal additive result is three distinct folders (subject to Settings ON/OFF duplicate policy). Turn Google website card **Exclusive ON** → that same chord now creates exactly one file in **`redown/google/`**, with no files in either other folder for that capture. On `youtube.com`, Google Exclusive doesn't match, so normal shortcut routing still applies. Turn Google Exclusive OFF → normal additive behavior resumes. If a multi-folder shortcut card itself is made Exclusive, require the user to pick exactly one of its folders as the single target.

**Required tests:** Activate Exclusive on an enabled Google website rule; screenshot on matching Google → exactly ONE Worker write to `redown/google/` even with duplicate Setting OFF and multiple otherwise-matching rules. On YouTube Google Exclusive doesn't apply; normal additive routing occurs. Turn Exclusive OFF and verify all contributing rules resume with unchanged saved configurations. Deactivate its card → the exclusive effect stops, card remains visible/editable; reactivate restores the same configured toggle. Validate selected shortcut-only Exclusive folder, permission failures, and switch persistence after restart. Verify repeated Chrome/retry events do not turn one exclusive capture into multiple files.

## Settings — Single file per screenshot per directory (DEFAULT ON)

**Exact user-facing setting:** Settings → Screenshot → **"Single file per screenshot per directory"**, toggle **ON by default** for new or upgraded profiles without an explicit stored value; persist OFF/ON across restart. Do not place this setting in the More → Screenshot website-to-location form, Screenshot2Here popup, or a new capture tab. Explain beside OFF: "Create one copy for each matching rule, even when several rules point to the same folder. This uses more cloud storage and Worker writes."

**ALL matching rules contribute; no most-specific-wins.** On one valid user-triggered screenshot shortcut press, match **every enabled saved shortcut card with that chord** whose website list (OR of its entries) includes the current trusted URL. Empty website list means all sites and **still matches alongside** narrower cards. Collect each destination attached to each matched shortcut card. Also collect **every enabled matching additive website → folder rule** from More → Screenshot. Each matched **rule ID + destination folder** contributes one intended delivery, regardless of overlap. A single card with two website entries that both match still contributes its destinations **once** (its website entries are alternatives, not distinct rules). Duplicate identical folders within one card's destination list are disallowed. Different shortcut chords are not triggered.

**ON / default (directory-level dedup):** Group intents by canonical authorized **provider + account + bucket + exact prefix**. Produce **exactly one screenshot file per distinct directory** for this one capture. Ten distinct matched rules pointing at one folder → **ONE object there**, not ten. Ten rules spanning three distinct folders → **ONE object in each of the three folders**. Receipt includes the identity of every contributing rule, intended deliveries, which were combined, and independently verified resulting objects.

**OFF (per-rule copies):** Do NOT collapse deliveries from **different matching rule IDs** just because they target the same directory. Fulfill **each matched rule→destination association** as a distinct Worker-side object write. Ten distinct matching rules pointing at the same folder → **TEN separate screenshot files there**. Generate collision-resistant distinct file keys (capture ID, rule ID and destination ordinal), with no overwrite. Record a rule-associated verification result for each copy. ON/OFF must not affect the site's rule matching, card persistence, shortcut assignment or screenshot capture logic.

**Transport and correctness in BOTH modes:** Exactly **ONE screenshot capture and ONE extension→existing trusted Cloudflare Worker image upload** per triggered action, regardless of matching rule count. Worker performs all server-side authorized writes; the current Worker has single-destination logic and needs a scoped extension to support these semantics. Securely authorize intended rule IDs/destinations, reuse existing File API/recorder/Raw-Secure exporter, and do not fake support for unbound buckets. Idempotency protects **retries of the SAME output intent** but must NOT collapse intentionally distinct OFF-mode rule copies. Use bounded Worker concurrency/memory, report partial failures truthfully, count matching rule IDs, unique directories, planned outputs, actual writes and verified/failed/unknown results. Do not log screenshot bytes.

**Required proof matrix:** With 10 enabled distinct overlapping shortcut/website rules targeting one directory, ON = 1 capture, 1 browser upload, **1 R2 file**; OFF = 1 capture, 1 browser upload, **10 R2 files with distinct keys**. Across three directories, ON = 3 R2 files, OFF = one per rule-to-directory association. With two website patterns matching inside ONE shortcut card, count the card once, not twice. With an all-sites shortcut card and a Google-specific card sharing the same chord, **both** contribute when on Google, and any matching additive Google website rule contributes as well. Turning a rule off leaves its saved card visible but excludes its output. A failed copy makes result partial; retry cannot inadvertently create extra files. Setting persists after restart.

## 2B. File Explorer directory right-click → Screenshot2Here (shortcut destination manager)

**This is a new owner-required QUICK ASSIGNMENT popup—not the full manager, not a route to the full manager, and not a request to screenshot File Explorer.** The sole full-manager entrypoint remains clicking the rule's own card under **More → Screenshot**.

Clicking it opens a **compact, aesthetically organized quick assignment popup** with the selected authorized **Cloudflare account → bucket → exact folder path** prefilled as the proposed destination, plus two ways to assign a screenshot shortcut:

1. **Type/capture a new keyboard shortcut** in an input (validate with the already built canonical shortcut resolver and Chrome keyboard constraints), or
2. **Choose an existing Screenshot shortcut** from a **bounded-height, vertically scrollable list** of all existing screenshot bindings, showing each chord, the rule name, site/URL scope, and current destination. The list has one clear selected state. A user can have more than 25 rules elsewhere; this chooser must scroll rather than overflow the popup.

**[Save]** is the single durable commit action, with Cancel/Close. Do not change any mapping before Save. When an **existing shortcut** is selected, saving **either APPENDS the selected directory to that specific shortcut rule's destination list, or REPLACES the explicitly chosen destination row, according to the user's selected mode**, without inventing a second rule, renaming the shortcut, modifying its user-defined website/hostname/exact-URL matcher, or changing other saved rules. In Replace mode, show **old destination → new destination** before Save; in Add mode, show the full existing list plus the new folder. When a **new shortcut** is entered, create a new screenshot rule bound to the exact selected directory; the user may optionally specify site/URL scope, or use the **All websites** default and refine it later on Screenshot Rules page. When a matching existing route is selected, let the user explicitly **Replace selected destination** OR **Add this folder** without losing other folders. Reject only unrelated Chrome command key collisions and invalid/duplicate conditions within a single rule; overlapping same-chord screenshot cards are intentionally additive.

**Important distinctions:** this `Screenshot2Here` choice **does not take a screenshot at Save time**. ## 3. Screenshot rule matching is ADDITIVE, not exclusive
