# P1 — Daily completed-download number on the EXISTING Chrome extension toolbar icon

**Requested:** November 19, 2026; **CORRECTED BY OWNER** November 19, 2026. **Status:** Next-Codex implementation request, not implemented.

## Exact UX — existing browser icon, NOT the Shelf

The owner means **the existing Click2Cloud extension icon in Chrome's browser toolbar** (the icon users may pin from Chrome's Extensions/puzzle-piece menu, next to the address bar). Put a small number/badge directly over that **existing extension action icon**. **DO NOT add a badge, counter, icon, toolbar item, heading, or any numeric indicator inside the Click2Cloud Shelf**: not in the Shelf header, top-right theme area, Explorer toolbar, Remotes, or Settings. Do not change the extension's base logo.

Use the native Chrome MV3 **`chrome.action.setBadgeText({text: ...})`**, with an accessible contrast `chrome.action.setBadgeBackgroundColor`, and use the **global action badge** (no tabId, not a page-specific badge). Chrome only provides limited badge text space (approximately four visible characters): show `0` when verified zero; otherwise compact unambiguous counts such as `1`, `12`, `999`, `1k+` for larger values (full precise number stays available in existing History). Preserve established toolbar click behavior and any existing icon/title semantics. The system browser UI and whether the icon is pinned are **not under extension control**: don't pretend the badge can always be seen when the icon is unpinned or that Chrome's global puzzle icon can be modified. **No separate user-facing popup or new Settings choice** for this counter.

## Daily count from verified canonical operation receipts

- Display the **number of distinct successfully completed Click2Cloud file transfers today**, with confirmed remote saves/download-to-cloud as the central use case. Include completed Click2Cloud-initiated local file downloads/exports when implementation provides trustworthy completion evidence; do not count unrelated Chrome downloads, failed/pending/cancelled operations, new browser tabs, readiness checks, or attempts.
- If a bulk ZIP export is confirmed complete by the browser and its archive inventory lists N distinct included original files, count **N files** in the daily badge, not the ZIP wrapper or generated metadata/receipt sidecars. Where delivery is not confirmed, keep the count unchanged. Repeated status events or worker restarts must never double-count; this minimal aggregate never creates a History entry or a receipt copy.
- **History MUST remain completely unchanged.** Derive the remote/right-click-save portion of the badge from the already-existing durable History/receipt authority using **read-only** calls, including `readRemoteResults`; do NOT add local downloads or bulk export jobs to History, or modify any History schema, UI, filters, writes or retention. For locally downloaded bulk files, if included in the badge, use a **separate minimal numeric day total driven by observed browser download completion** (not a full job/receipt history), and reconcile it without double-counting. Reuse the configured History timezone for day boundaries. ZIP sidecars and the embedded `RRReceipt-<time-stamp>-<job-number>.json` never count as independent downloaded files.
- At **local midnight in the existing configured History timezone** (or device timezone when unset), badge becomes `0` if no new completed file transfers exist, without requiring the Shelf to be open. A new verified completed transfer increments the new day's count. Account for timezone changes and daylight saving. Old-day History stays intact.
- Recompute/publish badge at Chrome startup, extension install/update/reload, on relevant verified receipt changes, and at rollover using a reliable MV3 service-worker-safe alarm/schedule (not `setInterval` in a permanently-running worker or Shelf page). Use persistence/reconciliation to survive worker suspension and browser restarts. Do not poll Cloudflare or scan remote files simply to refresh badge.
- If the underlying History data is temporarily unavailable, do not display a misleading verified `0`; preserve a known latest valid badge where appropriate or use a distinct limited-space unavailable indicator (e.g. `!`) with a short diagnostic; recover automatically when data becomes readable. Ensure the Chrome action calls fail gracefully without disabling other extension actions.
