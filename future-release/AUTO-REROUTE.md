# REDOWN — Auto-reroute future-release research

## Release boundary
This is a separate, deferred development branch based on REDOWN 0.3.30 commit 3fd22f78408dac44155647b211ea37b623450fc1. Do not merge into the current UX repair or launch release. Current product proposition: right-click remote saves and screenshots at $12/year (owner's stated price). No change to existing licensing or entitlement behavior in this branch. Owner approval required before integration, release or pricing changes.

Proposed staged roadmap (not committed release dates): first establish image interception; research archive interception and then video. Second release/year may offer Images and Video; third year may add Archive and Sound after validation. Research order and shipping order are deliberately distinct; owner decides final release scope. Do not advertise unverified formats or release unfinished categories.

## UX
- Provider card in Remotes: right-click > Auto-reroute > Images / Video / Sound / Archive. Same nested menu on a specific authorized Cloudflare bucket or folder. No obligatory separate setup screen.
- Show only actually tested formats in parentheses beside each category; use a provider-aware authoritative capability registry. Untested categories are not enabled for live routing.
- One active destination per category is the proposed starting contract; clearly indicate assignment, support reassignment/deactivation; avoid ambiguous duplicate routing. Existing Rules may provide review/management without being required for setup.
- Separate default REDOWN folder preference: default on for provider-level saves, reuse or create authorized REDOWN folder; off restores existing behavior; explicit destinations override; no automatic migration of existing files. Confirm provider-specific semantics before implementation; no silent bucket creation. This feature belongs here for now, not the launch repair branch.

## Engineering
Investigate actual Chrome downloads APIs and installed-browser lifecycle; temporary local staging is acceptable. Preserve original download on failure; never cancel irrecoverably before bytes are safely available and never delete a recoverable copy before independently verified cloud success. Restrict cleanup to exact owned staging objects/files, no unrelated deletion. Unsupported/unmatched downloads continue normally. Do not bypass browser security, site access controls, account scopes or consent. Handle expiring/authenticated URLs, blob and POST cases only where supported; otherwise leave original download alone. Pin authorized provider/account/destination at dispatch. Reuse V3+1 production APIs, save engine, queue, history, receipts and custom notification. Distinguish detected, matched, intercepted, transferred, verified, failed, skipped, canceled and unconfirmed states. Prevent duplicate operations and unsafe retries after ambiguous outcomes. No generic native success notification requirement introduced here; inherit approved notification behavior when integrating.

## Diagnostics and portability
Settings: export diagnostics ZIP, export/import versioned routing manifest, validate/preview before explicit atomic apply, no automatic downloads on import. No secrets or private bytes in exports. Default diagnostic ring retains newest 40,000 entries, optional uncapped debugging until available storage limit, report overwritten/dropped entries and any incomplete exports. Async bounded batching, no blocking save path, no unnecessary polling or loading entire history. ZIP includes all retained data from a consistent snapshot: manifest, summary, events/operations/failures JSONL, routing rules and environment (redacted). Retention applies to diagnostic events only, not history/receipts. Include operation and browser download IDs, matching decision, format, authorized destination identity, bytes, integrity evidence, duration, transfer method, local disposition, retries, errors and final state. Report verified success rate with explicit denominator and pending/unconfirmed counts. Reuse existing recorder where possible.

## Agent-native engineering
Human and agent interfaces call same underlying logic and authorization. Document callable configuration, manifest validation/import/export, matching preview, operation inspection, statistics and diagnostic exports through existing scoped API; no new public endpoint. Deterministic test adapters and structured receipts; no production fault injection, duplicate engine or gratuitous network overhead. Test normal and failure scenarios in isolated fixtures, integration and installed Chrome/live separately. Independent bytes/hash or provider-supported equivalent verification; do not equate upload response or interception with success. Verify rule precedence, each format/provider, duplicates, interruptions, expired auth, staging cleanup, restart, storage limits, cap wraparound and uncapped export completeness. Live only with explicit approval, dedicated authorized QA destination, bounded costs and owned-object cleanup. Never claim unexecuted tests passed.
