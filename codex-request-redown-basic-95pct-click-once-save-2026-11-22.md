### Privacy and security boundaries

- Preserve the rule: **providers receive file bytes plus the required filename/metadata, never source/page URLs or browsing provenance**; keep URLs only in local History under existing privacy controls.
- Browser-origin access must have user-visible Chrome permission/consent. Broad all-sites access is powerful; evaluate its Chrome install/update warning and review implications explicitly. **Do not grant permission silently or make false claims of all-site access**. Respect Chrome's withheld-site and enterprise policies.
- No source-side credential extraction, cookie copying, browser security bypass, unauthenticated proxy/relay, or access-control circumvention. The old implementation frequently uses `credentials:'omit'`, whereas current Basic uses `credentials:'include'` and `redirect:'follow'`. Measure which combination works safely for real permitted source URLs; do not assume those flags alone fix Bing.
- Keep source URL validation, response MIME/body guard, private-address restrictions, bounded memory, aborts and provider-confirmed writes. Do not turn HTML or an inaccessible endpoint into a fake saved file.
