### Code evidence and suspected failure chain (verified in current main source)

1. `extension/app.mjs` in `fileActionGUI('rename',...)` invokes `run(name,false)` — the ordinary Rename path does not request setup and does not use the `offerFilePreparation` recovery wrapper used by other file actions.
2. `src/api/service.mjs` `fileAction` calls `prepareFileWorker(operationTarget,{sourceBucket,authorizeSetup:params.authorizeSetup})` **before** dispatching the rename.
3. `src/cloudflare/onboarding.mjs` `ensureFileWorker` checks the existing prepared plan: it accepts an up-to-date, broad ready plan, but otherwise can throw `FILE_SETUP_APPROVAL_REQUIRED` when neither explicit authorization nor suitable saved approval is present.
4. `extension/app.mjs` `fileError('Rename', error)` turns that error into the unhelpful message above.
5. `src/explorer/r2-adapter.mjs` already maps Rename to the existing `cfRenameEntry` command; `src/cloudflare/file-transport.mjs` routes that command to the existing remote file-operation transport.

**Diagnostic caveat:** The code explains where the error comes from, but it does **not yet prove why the owner's particular bucket was considered unprepared**. Inspect current plan state, target identity, scope, ready-version/digest evaluation, session and existing write authorization before selecting the fix. Do **not** assume an OAuth permission issue or send the user to reconnect without evidence.

## Suggestion 4 — NEW: Windows Explorer-style marquee / rubber-band file selection

**Owner concept:** In the **right-hand File Explorer pane where files are listed**, click on an empty patch of the file area and drag the mouse **upward** (or down/diagonally) across files; as the pointer sweeps the entries, they become selected, just like Windows File Explorer's **marquee selection** or **rubber-band selection**.

**Proposed interaction details:**
- Begin only on a primary-button pointer-down on **empty file-pane space**, not inside a filename, existing row button, editable text, scrollbar, folder tree, header, resize splitter or action menu.
- While held, draw a subtle theme-compatible translucent rectangle / border and select all file rows or tiles it intersects; dragging up, down and diagonally works.
- When starting in a different selection mode, ordinary marquee replaces selection; modifier semantics such as **Ctrl to add/toggle** and **Shift to extend** should be explicitly specified to match Windows conventions and REDOWN's existing Shift/Ctrl selection rules without conflict.
- A tiny click without dragging should behave as a normal background click; don't accidentally initiate selection, menu changes or file moves. Use a small drag threshold and don't interfere with double-click-to-open, context menus, keyboard navigation, rename or preview.
- Optional bounded **edge autoscroll** while holding and dragging near the top/bottom of the file pane; speed capped. Support upward dragging over earlier files even when the list is scrolled. On release stop immediately, remove overlay, and retain selected items.
- **Performance and crash resistance:** REDOWN uses a *virtualized* list/grid, so **do not mount the full directory or scan the entire object list every pointer frame**. Compute selection by logical file index, stable file ordering, fixed row/column geometry and visible viewport bounds; requestAnimationFrame/throttle updates only as needed. Bound selected-key state and calculations; avoid memory growth and stale selected indices when sorting/navigating.
- Cancel cleanly on `Escape`, pointercancel, lost capture, navigation, dialogs and Shelf closure. Avoid scroll/pointer-event leaks and stale marquee overlays.
- Support List/Details and grid where practical, and all themes/light/dark; ensure proper contrast and accessibility (keyboard selection remains usable).
- Test 1, 4, 100, 1,000 and larger virtualized directories, selection while scrolling up/down, drag over empty areas, Ctrl/Shift, first/last items, fast pointer moves and repeated cycles with no hangs, excess CPU, memory leaks or broken file operations.
- **No additional Worker or remote service.** This is ordinary pointer/selection UI, not a cloud transfer. It should not crash when implemented with virtualization-aware bounded logic, but must be proven with browser stress tests.
