## Production contracts and failure recovery

- `src/history-v2/records.mjs` owns the version-1 projection. The coordinator accepts retained receipts and observes only recognized save kinds. Provider execution, key assignment, permissions, retries and verification stay with the existing owners. Native and screenshot code and the manifest remain byte-for-byte unchanged. A source that recorded no attempt supplies no reconstructable data.
- `createHistoryArchive` owns the `click2cloud-history-v2` database. Archive records, counts, exclusions and policy state commit transactionally. `chronology` and `ordinary` index `(orderAt, recordId)` in UTC. Full-archive jumps use day counts and then an indexed seek from the closer end. Range-restricted pages use indexed count and cursor advance inside the range. An unusually dense day can still require a deeper in-day scan. Legacy owner storage is read in bounded key pages. Its older monolithic compatibility value must be read as the owner stored it.
- `createHistoryCoordinator` writes bounded batches and records durable backfill progress. Startup resumes the scan. A subsequent startup can replay the available receipts safely. A source failure can leave coverage incomplete while records already accepted stay available. The runner is triggered from Queue surfaces, and offline source changes remain in the owner stores until the next scan. A standard pending receipt cannot prove that a worker is still working remotely. The job keeps the last owner update and permits explicit receipt inspection.
- `createLiveJobs` owns a separate IndexedDB database. It indexes Working, Needs attention, and Waiting in display order. The independent view uses 10-row windows and preserves local scroll and filters. Durable owner success with a failed accounting write remains an attention item. Successful accounting makes the job leave the live list. Acknowledgment is local and preserves the save record. Job history stores compact replay markers. Queue and History can mount separately via `mountLiveJobs` and `mountHistoryV2`.
- Default Hide filters terminal time before counting and pagination. OFF shows retained records. Delete starts at the user-approved effective time and applies only to V2 metadata. Capped retention is opt-in and the suggested 200,000 is editable as a positive safe integer. Clear requires confirmed scope, retained count and revision, with optional export-first. Large clears commit in batches and resume after interruption. Exact ID exclusions preserve suppression for removed attempts while accepting newly observed distinct IDs even if their timestamps are older. Exclusions have a disk cost proportional to removed record IDs. Device/browser quota bounds Unlimited storage.
- `snapshot` uses an origin lock for a frozen revision during indexed reads and sealing. Source receipts continue to be recorded by the existing owners during export. ZIP32 output uses disk-backed OPFS staging, 128-record reads and a 256 KiB format buffer. The temporary file is removed on completion/failure and orphan staging files are scavenged under a separate origin lock on the next export. Output exceeds capability if the ZIP32 byte limit, device quota or Chrome download authority is reached. There is no partial success. The archive's CRC-32 and a chained SHA-256 digest over fixed-size blocks have an independent Python verifier. The ZIP describes recorded evidence and performs no live provider verification.

## Record and adapter interfaces

| Version 1 field group | Contract |
| --- | --- |
| Identity | `recordId`, `sourceRecordId`, `sourceApi`, `attemptId` are strings. `actionId` and `outputId` are optional source identifiers. `objectId` is the observed object-version reference when supplied. |
| Chronology | `orderAt` is the immutable UTC sorting key. `requestedAt`, `startedAt`, `terminalAt`, `verifiedAt` and `recordedAt` are epoch milliseconds or `null`. `observedAt` orders receipt updates. The sort key for a genuinely undated record is `-1`. |
| Outcome | `status` is Working or Waiting for owner-backed jobs, or a terminal verified, uploaded, blocked, failed, canceled or uncertain result. `verification` and `errorCode` hold observed evidence independently of local accounting. A reported percentage is optional and indeterminate without an owner value. |
| Metadata | `provider`, `kind`, filename, MIME, size, destination, owner links, mode and safe upload snapshot. URL fields keep separate meanings and use `null` where absent. `capabilities` describes the existing authorized viewer, navigation or recovery options for that record. |
| Adapter | The existing `readQueueReceiptPage(cursor)` yields one primary-key batch and a continuation. `readRemoteResultsById(ids)` fetches a bounded set for receipt delivery. Neither adapter writes provider state. `readOwnerAttempt` projects one standard record or one record per observed screenshot output. |
| Query and export | `page` returns exact query count, current and total pages, archive revision and one row window. `snapshot` supplies an async iterator plus expected count and revision. `subscribe` forwards local changes to the independent mounts. The UI and deterministic tests use these same operations. |

The measured archive maintenance duration and readiness gates are explicit in the executable evidence. Basic providers, native context-menu behavior in this environment, installed Chrome use of the OPFS-to-download path, live OAuth and live 401/403 behavior remain open acceptance items. A worker restart can leave an owner pending receipt without current status. The last update and authorized inspection remain available in Live Jobs.
