## Required deliverable
1. One compact Settings card titled Python Laboratory, OFF by default. Start session, select an existing authorized QA bucket, explicit read/write scope and bounded session, pairing code approval, copy exact Windows CMD, connected/disconnected status, end/revoke. No additional tabs, separate dashboard, or settings clutter. Reuse current theme system. Advanced configuration belongs to Python. Clear errors and reconnection. Do not claim live connection until an actual handshake succeeds.
2. Reusable local Python SDK/CLI and authenticated native relay, adapted to current installed extension. Python invokes the same production operations as GUI; never export Cloudflare OAuth credentials or grant websites arbitrary access. Explicit origin/extension identity validation, authenticated local-only connection, expiring single-use pairing, least privilege, exclusive fresh QA prefix, request/byte/concurrency/time limits and revocation. Native host installation is explicit and documented. No public endpoints, remote arbitrary execution, expanded provider permissions, or automatic Worker deployment. No bypass of Chrome policy. Re-authentication via normal approved flow.
3. Capability discovery, typed operation outcomes, independent remote readback and SHA-256, durable incremental journals, reproducible seed, bounded progress and cancellation, safe read-only reconciliation, no blind replay of uncertain mutations. Preserve original offline laboratory and receipts. Avoid duplicate logic; audit existing API entry points and extend shared production services only where necessary.
4. Support normal files and operations: realistic valid images (JPG PNG WebP GIF SVG), documents (PDF DOCX), text (TXT MD CSV JSON YAML XML), media (MP4 WebM MP3), archives (ZIP CBZ), nested/multiple folders, Unicode, empty files and conflicts. Exercise upload/download, metadata/list/search, preview, URL generation, copy/move/rename/delete and mkdir where supported; mutation limited to exclusively owned QA prefix, no public-access policy changes. Record unsupported operations explicitly, distinguish true-remote URL saves from local uploads, and test recovery, queue/history consistency, session lifecycle and authorization. Human GUI acceptance remains separate.
5. Minimum heavy acceptance: ONE valid complete media file of at least 100,000,000 bytes per transfer, 20 simultaneously active uploads, 20 simultaneously active downloads, then 20 uploads + 20 downloads simultaneously (40 active; 4 GB payload excluding extra verification traffic). Downloads use pre-seeded verified distinct fixtures, not partially uploaded files. Prove overlapping real transfer activity rather than queue count. Repeat bounded cycles; test interruption and reconciliation. Independent streamed SHA-256 for every final object and downloaded file, sizes, identities, no duplicates, no false success. This is an engineering gate, not a current capability claim. Use bounded buffers, disk-backed staging as needed, backpressure, fair provider-aware scheduling, per-operation checkpoints and incremental reports; no whole 100 MB payload in RAM or unbounded database growth. Respect provider limits, disk capacity, and actual resource budgets. Do not weaken integrity to meet concurrency. Profile working-set RSS, disk, throughput, p50/p95 latency, active overlap, queue and GUI responsiveness. Document memory/disk budgets, failure behavior and actual measurements. Larger aggregate workloads and file counts are future design goals, not acceptance claims.
6. Python profiles Quick, Everyday, Comprehensive, Heavy, Endurance, Custom; small deterministic fixtures and valid media generation, independently vary size/count/concurrency/duration, gradual tiers, stop advancing at first failure, preserve evidence. Budget preflight includes storage, temporary disk, requests, bandwidth, explicit owner-approved spend and separate live-write consent. Default offline. Heavy live runs require explicit owner approval; never launch real cloud mutations from Codex. Do not bundle large media or private reports/credentials.
7. Codex prioritizes implementation and owner-runnable verification scripts rather than spending its compute on long workload runs. Provide fast focused contract smoke checks only as feasible; no fabricated results. Windows CMD commands must be copyable single-line chains using && (avoid delayed environment-variable expansion pitfalls). Include install, build, pair, doctor, everyday, heavy, receipt collection, and recovery instructions. Preserve exact tested commit and label offline/native fixture/live/GUI results separately.

## Timeboxed handoff
Aim to complete as much as possible within a 45-minute session, not necessarily use all 45 minutes. By minute 35 prepare a concise handoff with exact changes, outstanding blockers, and locally executable verification. Push to this dedicated GitHub branch by minute 45 with handoff ready; if finished sooner push sooner. Do not represent an unrun live test as PASS. Keep scope focused, separate incomplete gates, and do not change existing branches. The current 0.3.32 offline results are six owner-run passes, not live acceptance.
