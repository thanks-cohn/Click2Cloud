## 1. Ordinary application record
Name every owned replica rdata.txt. The text file has three functional sections and one permanent closing line:
- Friendly permanent header: identify ReDown application data, including free allowance continuity, explain that manual edits may interfere with recovering the current state, and identify the purpose and accessible removal/disconnect options. Do not falsely imply unrelated application functionality or customer cloud files depend on it.
- Versioned manifest-like genuine state: opaque entitlement/account references, schema/policy version, original validated installation/enrollment anchor, period identity, last validated renewal and next renewal, revision, compact symbolic ten-pool state, bounded operation reconciliation and available integrity evidence. Store only necessary actual state. No credentials, private files, device fingerprint, fake configuration or misleading terms. Use one deterministic encoder/decoder and documented mapping; no large editable quantities that grant privileges, unnecessary if/else chains, random padding, word/line counts as authority, or security claims based on secrecy.
- Creator's acknowledgments: approximately 200 words of the owner's own exact text, gratitude, personal hopes and wishes. Use a versioned canonical owner-supplied original and a deterministic shortening projection of confirmed current-period use. For a verified successful free logical file, one designated fragment disappears; the complete original returns on validated renewal. Define 100 stable removable fragments from the supplied text, preserving order and all remaining text exactly; no invented names or replacement prose. The message is a decorative reflection of validated accounting, not an independent allowance source. A release can change the template without resetting credits; store template version and support old versions safely. User's exact full message has not yet been supplied: use clearly labeled synthetic fixture text only in tests and request owner-approved final content before shipping the Easter egg.
- Permanent final line, byte-for-byte in every rendered record (including exhausted and renewed): Thank you for enjoying ReDown.
The header, manifest and decorative message use clear parsing boundaries; editing the message alone cannot create credit or invalidate otherwise valid authoritative state. No real personal message text needed for core functionality. Use UTF-8, bounded file size, robust versioned parser and predictable line endings. Document the format and symbolic mapping for the owner. No publicly exposed new API or key material. A client-side mapping or checksum deters accidental modification but is not authentication.

## 3. Fixed allowance and monthly anniversary
Ten pools of exactly ten fixed slots: basic clouds collectively (general/right-click/screenshot/chord-click/manual upload), R2 separately (same five). Limits compiled/policy-defined, never supplied by the record: 10/pool, 50/group, 100/enrollment-month. Compact symbolic state or fixed-slot representation may encode occupancy; no file value, fabricated symbol, added word or extra slot independently grants entitlement. Reserve once per logical file before admission, settle exactly once on verified publication, release only on proven nonpublication, preserve uncertain reservations. Matching feature bonus first then its group's general pool; no cross-group/feature borrowing. Reads, retries, metadata and paid usage do not debit. Preserve existing batch choice, source and destination freezing, and verified paid unlimited behavior.
Renew on each monthly anniversary of the first validated installation/enrollment anchor, not first of calendar month, not 30-day duration and not each reinstall. Proposed deterministic edge rule for implementation: UTC original day and time; shorter month clamps to final day and subsequent month returns to original anchor day (e.g. Jan 31 -> Feb 28/29 -> Mar 31). Confirm/display actual next timestamp; avoid local timezone/DST drift. For existing installations recover the known installation/enrollment anchor; where unavailable use first validated enrollment, never invent an earlier date. Validate time using available trustworthy evidence, preserve last validated period and prevent backward/duplicate or arbitrary clock-jump renewal. No carryover. If several months elapsed, grant only current period once, not accumulated allowances. Late settlements use original admission period; old uncertainty does not consume new period credits. Persist anchor locally and in every replica. Clock/security limitations without trusted time are explicit.

## 4. Enrollment, missing files, modified files
- Known valid state (local or any compatible cloud replica): restore consumption and original anchor, reconcile newer evidence; absent copies never grant extra credit.
- Both/all copies missing while ReDown remains installed: retain local validated state and original anniversary; continue valid remaining credits and automatic renewal at next validated anniversary. Do not reset because a file was deleted or silently recreate explicitly removed metadata.
- Invalid/corrupt/rolled-back manifest: attempt recovery from valid local/other replica. If no valid current-period eligibility can be established but original anchor is trustworthy, restrict unverified free admissions until state recovers or next independently validated renewal. Distinguish confirmed exhaustion from unavailable/unverified state; allow retry and truthful recovery information, never treat a typo in decorative prose as evidence of cheating. Existing reads/retrieval and verified premium remain available. No forced checkout, irreversible lockout or premature reset.
- Genuine new install or complete reinstall with no surviving valid or known prior enrollment evidence and all relevant authorized established checks conclusively absent: owner-approved new-customer enrollment, full ten pools and new anchor. Unknown/unavailable/corrupt is not conclusive absence. Do not demand access to unrelated clouds or other accounts. If trustworthy local eligibility already exists, do not wait for unrelated cloud checks. Do not covertly fingerprint or track deleted records. All-copy deletion plus uninstall can therefore reset allowance; this limitation is accepted for V1.
- Existing paid license stays intact. Previous valid current-policy state survives filename/schema migration; validate and preserve usage and anchor before replacing owned legacy records. Do not grant a fresh period solely for changing formats. For genuinely different old pre-release allowance schemes, inspect actual deployed state; propose one-time transition to the new plan preserving paid entitlements and obtain owner approval if such records exist. Never invent migration evidence or delete historical receipts.
No paid activation required to recover a valid trial; no new payment integration or mandatory server in Part 2.
